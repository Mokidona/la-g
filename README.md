# Лендинг «Реабилитация и ЛФК в Астане»

Статический сайт: `index.html` (RU), `kz.html` (KZ), `styles.css`, `script.js`
и картинки в `assets/`. Сборки, npm-зависимостей и базы данных нет — HTML
открывается напрямую и раздаётся любым статическим сервером.

Тексты и фотографии, которые были сохранены в админке, уже перенесены в эти
две страницы, поэтому сайт выглядит ровно так, как выглядел до её удаления.

## Правка контента

Тексты лежат прямо в разметке, менять их можно в любом редакторе:

- `index.html` — русская версия, `kz.html` — казахская. Правки нужно вносить
  в обе страницы, иначе языки разойдутся.
- Заголовок и описание для поисковиков — `<title>` и `<meta name="description">`.
- Телефон — ссылки `tel:+7...` (они же открывают окно записи через `script.js`),
  ссылки на WhatsApp и 2ГИС — обычные `<a href>`.
- Фотографии — файлы в `assets/`; замените файл с тем же именем или поправьте
  `src`. Ссылки на картинки относительные (`assets/...`), поэтому сайт работает
  и из подкаталога, и при открытии файла напрямую.
- Кнопки RU/KZ переключают страницы и запоминают выбор в браузере.

Стили — в `styles.css`. Цвета темы заданы переменными в `<style>` внутри
каждой страницы (`--lime`, `--purple`, `--pattern` и т. д.), узор фона —
`assets/pattern.jpg`.

## Структура

```
index.html          страница на русском
kz.html             страница на казахском
insult.html         страница «Реабилитация после инсульта в Астане» (RU)
styles.css          стили лендинга
script.js           аккордеон FAQ, окно записи, переключатель языка
assets/             фотографии, иконки, узор (WebP)
assets/fonts/       локальные woff2 Inter, Manrope, Gravitas One
assets/uploads/     изображения, загруженные ранее через админку
robots.txt          разрешает индексацию и указывает на sitemap
sitemap.xml         карта сайта с hreflang для RU, KZ и страницы услуг
favicon.svg         иконка сайта
Caddyfile           статическая раздача, кеш и заголовки безопасности
Dockerfile          образ caddy:2-alpine со статикой
docker-compose.yml  запуск за Traefik для kinesiolife.kz
```

## Производительность

Страницы не обращаются к сторонним доменам — шрифты лежат локально.
`styles.css` начинается с блока `@font-face` (переменные Inter 300–700
и Manrope 300–700, Gravitas One 400), файлы — в `assets/fonts/`. Наборы
`latin`, `cyrillic` и `cyrillic-ext` подключены через `unicode-range`, поэтому
браузер скачивает только те, что нужны для языка страницы (казахские буквы
ә, ғ, қ, ң, ө, ұ, ү, һ, і живут в `cyrillic-ext`).

Изображения отдаются в WebP: `hero.webp`, `specialist-zuhrab.webp`,
`uploads/manual-table.webp`, `pattern.webp`. Оригиналы `.jpg`/`.png` оставлены
в репозитории как источник, но страницы на них больше не ссылаются (кроме
`og:image`, которому нужен JPEG для соцсетей). Если меняете фото — положите
рядом `.webp` с тем же именем и обновите `src`.

Кеш для `/assets/*` — 30 дней (`Caddyfile`), HTML/CSS/JS — `no-cache`
с ETag, поэтому правки видны сразу после пересборки образа.

## Локальный просмотр

```bash
python3 -m http.server 8080
# http://localhost:8080/       — RU
# http://localhost:8080/kz.html — KZ
```

## Docker

```bash
docker compose up -d --build
```

- Контейнер слушает порт **80**, Traefik проксирует на него домен
  `kinesiolife.kz` (см. `docker-compose.yml`).
- Тома и переменные окружения не нужны: всё содержимое сайта лежит в образе.
- `Caddyfile` добавляет gzip/zstd, кеш на `assets/` и заголовки безопасности;
  `/healthz` отвечает `ok` для healthcheck.

Если после правок контейнер отдаёт старую страницу, пересоберите образ —
`docker compose up -d` сам его не пересобирает:

```bash
docker compose build landing && docker compose up -d --force-recreate landing
```

`docker compose ps` должен показать `Up (healthy)`, проверить ответ можно так:

```bash
curl -I https://kinesiolife.kz/
curl -I https://kinesiolife.kz/kz.html
```

## SEO

У каждой страницы свои `title`, `description`, `canonical` и взаимные
`hreflang` (`ru` — главная, `kk` — `kz.html`, `x-default` — главная).
Отдельные страницы под услуги (`insult.html`) нужны, чтобы попадать в выдачу
по своим запросам: одна главная не ранжируется по всему ядру. На новую
страницу ссылаются пункт списка в блоке «Когда можно и нужно заниматься»
и меню в футере — без внутренних ссылок поисковик её почти не обходит.
В разметке есть микроразметка Schema.org: `MedicalClinic` (название, телефон,
полный адрес с индексом, координаты, карта, цена, соцсети) и `FAQPage`
с вопросами из секции FAQ. Адрес в разметке совпадает с видимым адресом
в футере — это требование Google к локальным данным.

Адрес взят из карточки 2ГИС и продублирован в футере всех страниц
(проспект Абылай хана, 24/1, цокольный этаж). Часы работы в разметку
пока не добавлены — нет подтверждённого графика: 2ГИС показывает только
время открытия. Как только график будет известен, добавьте
`openingHoursSpecification` в JSON-LD и строку в футер. Первое фото грузится
с `fetchpriority="high"`, остальные — `loading="lazy"`.

После деплоя проверьте, что служебные файлы доступны:

```bash
curl -sI https://kinesiolife.kz/robots.txt
curl -sI https://kinesiolife.kz/sitemap.xml
```

Дальше сайт добавляется в Google Search Console (свойство типа «Домен»
проверяется DNS-записью) и туда же отправляется `sitemap.xml`.
Для статистики посещений подключается Google Analytics 4 или Яндекс Метрика —
счётчик вставляется в `<head>` обеих страниц.
